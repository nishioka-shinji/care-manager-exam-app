# 2026-09-20

## ケアマネ過去問アプリを Flutter で作り直す

Web 版 care-manager-exam のデザインと挙動を踏襲し、Flutter で作り直した。コードは共有せず Dart で書き直している。PR: nishioka-shinji/care-manager-exam-app#1

ホーム・演習・結果・履歴の 4 画面を、土台（モデル・採点・永続化・テーマ）から順に積み上げた。調査 → 計画 → 合意 → 実装ループで進め、10 タスクに分解した。

移植で引き継いだ判断は次の 4 つ。いずれも Web 版が意図して選んだもので、推測で変えないよう CLAUDE.md の不変条件に書いた。

- 合否を判定しない。合格基準が年度ごとに補正されるため、得点と正答率だけを示す
- 選択肢をタップしても設問を作り直さない。作り直すとスクロール位置が飛ぶ
- 確認はネイティブのダイアログを使わず自前のシートで出す
- 保存済みの得点を信用せず、回答から採点し直して表示する

採点ロジックは移植の中核なので、Web 版の実装を node で走らせ、実データ 60 問に対し 300 ケース・11,191 問を突き合わせて一致を確認した。正答率の丸めも 7,383 通りの全数比較で差がないことを見ている。

Pixel 8（Android 16）の実機で 60 問の通し演習・中断と再開・復習・履歴の削除・ダークモードの追従を確認した。macOS は Xcode 未導入のため未検証として残し、README と CLAUDE.md の両方に明記した。

### 移植元の最新を取りこぼした

着手時に移植元を git fetch せず、24 コミット遅れたローカルの main を読んで移植を進めた。実機確認で「問題種別が 1 種しかない」「一問一答モードがない」と指摘されて発覚した。取りこぼしたのは全 16 年度のデータ、一問一答モード、正誤記録の年度スコープ化、ホームの年度カード刷新。

今回は対応せず PR の未対応事項として明記した。再発を防ぐため、移植元を読む前に fetch する旨を CLAUDE.md に書いた。

### 下部のボタンがシステムのナビゲーションバーに隠れる

実機で見つかった。Web 版は下部バーと確認シートの両方で safe-area 分を下の余白に足しており、その移植が漏れていた。確認シート側は対応が丸ごと無かった。

最初 ConstrainedBox(minHeight:) で直したが、高さの上限がないため Scaffold の緩い制約が AppButton 内の Align まで伝播し、ボタンが画面全高のタップ領域になって本文が操作できなくなっていた。サブエージェントの指摘で気づき、実測で裏を取ってから高さを締める形に直した。見逃していれば本文が一切タップできないアプリになっていた。

余白は viewPadding と padding の大きい方を使う。Android 15 以降の全画面表示では 3 ボタン操作のとき前者が 0 を返すことがあるため。

### テストが回帰を検出できない問題が繰り返し出た

「全件 pass するが本番コードを壊しても落ちない」テストが 4 回見つかった。レビュアーがミューテーションを当てて発覚したもので、内訳は次のとおり。

- ホーム画面のフッタ末尾判定が、位置比較の相手が悪く末尾から外しても成立していた
- 結果画面のグリッドが、色もレイアウトも見ておらず旧実装に戻しても通った
- 履歴画面で警告バナー・削除ボタンの条件・モードラベル・日時表示の 4 項目が未検証
- テスト側にシェル構造を書き写していたため、本番だけ壊しても追随せず検出できなかった

最後のものが最も質が悪く、本番の AppShell に不具合を再導入しても全件 pass のままだった。本番とテストで同じウィジェットを共有する形に直し、本番だけを壊して 4 件が落ちることを実測した。

以降は実装時にミューテーション確認を課す運用にし、CLAUDE.md にも書いた。

### 通し確認で見つけた実バグ

画面をまたぐ受け入れ確認を書いたところ、結果画面から「ホームへ」で戻っても直近の履歴が更新されない不具合が出た。Navigator が既存の画面を使い回すため initState の読み込みが走らないのが原因で、Web 版は画面を開くたび描き直す仕様だった。RouteObserver と RouteAware で戻ったときに読み直す形にした。

あわせて、再開カードの進捗を検査するテストが、この不具合のある挙動を正しい期待値として固定していたことも分かった。移植元の表示仕様から独立に検証してもらい、正しい値に直した。

- 事象: reviewer が PASS を返した後、レビュアーがミューテーションを当てて「全件 pass するが本番を壊しても落ちない」テストを 4 回検出した。T7 のフッタ末尾判定、T8 のグリッド、T9 の 4 項目、テスト側へのシェル構造の書き写し

- 分類: 指示不足。触ってよい範囲を狭めすぎ、移植の質を落とす方向の妥協を誘発した。T9 のケースは既にホーム画面が解決済みの問題でもあった

- 事象: T7・T8 が差し戻し上限（2 往復）を超え、3 回目のレビューまで到達した。いずれも修正が新たな問題を生んだため（T7 はテスト土台の差し替えで検出力を失い、T8 は破損耐性の修正で復習対象の判定が変わった）

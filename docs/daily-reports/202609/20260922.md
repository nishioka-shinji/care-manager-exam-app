## 一問一答モードを移植し、正誤記録を年度スコープ化する

PR#1 で取りこぼした一問一答モードを移植した。あわせて正誤記録を年度スコープ化した。PR: nishioka-shinji/care-manager-exam-app#3

着手前に移植元を git fetch したところ、ローカルが 24 コミット遅れたままだった。前回の事故と同じ状態だったので、origin/main に追いついてから仕様を読んだ。突き合わせたのは 7b46684。

一問一答は 1 問ごとに答え合わせを確定し、その場で正誤・正解番号・解説を出す。途中でやめられ、答え合わせ済みの問だけを母数に採点する。正誤は答え合わせのたびに 1 問ずつ記録し、終了時には記録しない。途中でやめてもホームの復習対象に反映させるためで、両方で記録すると二重に数えてしまう。

正誤記録は問番号だけをキーにしていたのを年度ごとに分けた。一問一答が年度付きで記録するため前提になる。既存の保存データはスキーマバージョンではなく中身の形で判定して移行する。移行先を第 28 回に固定してよいことは、データの年度が 1 件であることと移植元の定数から確認した。

### 範囲を決めた判断

年度スコープ化を今回に含めるかをユーザーに確認した。一問一答だけなら現状の 1 年度では不要だが、16 年度分を後から入れるときにマイグレーションが必要になり二度手間になる。含める判断をもらった。

全 16 年度データの取り込みとホームの年度カード刷新は今回やらない。移植元にある「本番通し」ボタンの問数 0 非活性も、今回の変更とは無関係な既存の差異なので触っていない。

### 不変条件 2 をどう守ったか

答え合わせでスクロールが飛ばないことが最大の関心事だった。コントローラの通知をそのまま受けると設問ごと作り直してしまう。画面の構造が変わる 4 つの値だけを見て再構築を絞り、答え合わせ済みかどうかは設問ごとの ValueNotifier に分けた。移植元も選択肢の DOM を作り直さず属性の上書きだけで解説を出している。

検出方法にも判断が要った。スクロール位置だけを見るテストでは再構築を検出できない。ScrollController が同一インスタンスなら位置を保つためで、実装者が実測で気づいてウィジェットが作り直されていないことを直接見る形に切り替えた。

### 中断セッションから答え合わせ済みの問が消えていた

レビューで実装の不具合が 1 件見つかった。設問を移動したり選択肢を押したりすると、答え合わせ済みの問番号が保存データから消える。「答え合わせして次へ」という一問一答の基本操作で必ず踏む。

中断して戻ると答え合わせ済みの問が未答え合わせに戻り、選択肢が再び編集できてもう一度答え合わせできてしまう。正誤が二重に記録され、この実装の目的そのものが破れる。さらに結果画面へ進めなくなる。

原因は不変クラスを手で組み立て直していたこと。フィールドを足すたびに、作り直す箇所すべてで渡し忘れがないか人手で保証する必要があった。答え合わせ済みの問番号はこの PR で足したばかりのフィールドで、まさにそれを踏んだ。移植元は同じオブジェクトを書き換える作りのため構造的に起きない差分だった。copyWith を入れて 3 箇所すべてを経由させる形に直した。

### 結合テストに本番構造を書き写していた

通し確認のテストが、本番のルーティングをテスト側に書き写していた。前回の日報に同じ事故が記録されており、CLAUDE.md にも書いてある。

書き写した結果、本番にある画面シェルの配線・履歴更新のための RouteObserver・テーマがテスト側から抜けていた。とくに RouteObserver は「結果画面からホームへ戻っても履歴が更新されない」不具合を直した経路で、この通し確認はまさにそこを通る。本番の App をそのまま起動する形に書き直し、RouteObserver を外すと落ちることを実測して裏を取った。

統合レビューで、同じ穴が main の時点から残っていることも分かった。画面シェルの配線を外しても全テストが通る。既存のルーティングテストがテスト側でシェルを挿しているため。前回の対策はクラスの共有までは達成したが、配線の共有には届いていなかった。今回の変更が原因ではないので PR に既知の限界として書き、別タスクとして残す。

### 検出できないと判断したもの

答え合わせ時の書き込みを待たずに進む形に変えても検出できない。永続化の実体が具象クラスで、書き込み順序を観測できる代役を差せないため。テスト専用の仕掛けを本番に入れる案も出たが、レビュアーが 3 通り試したうえで、呼び出し先が先頭で待つ構造のため観測できる差が存在しないことを特定した。検出できないのではなく差が無いという結論で、仕掛けを入れても同語反復になる。理由をコードに残して見送った。

同様に、回答状況シートを閉じる順序も検出手段を作れていない。実装は移植元と同じ順序を保っている。

Pixel 8（Android 16）で一問一答の通し動作を確認した。答え合わせでスクロールが飛ばないこと、下部バーの切り替わり、答え合わせ後の選択肢の固定、前の問への復帰、回答状況シートの正誤色分け、部分採点、中断と再開をまたいだ答え合わせ済みの保持まで含めて問題なし。
